Task 5:
Why use application context .. plz list some uses?
->
Automated Dependency Injection (DI): we don't need to create objects manually, the IOC container
does this for us. It makes the system loosely coupled.

Lifespan and Memory Management (Bean Scopes): 
its helps to control the scope of a bean, and do not rely solely on POJOs. There are multiple
scopes that we can achieve like: Singleton, Prototype, Webscopes

Early Configuration Error Checking: if we make any errors in the Configuration file, as during 
compilation Singleton objects get created, it will show us the errors immediately.

Modern Support For Annotations: it provides various Annotations support that increases code
readability and Clean Connectivity with the Classes. there are Annotations like @Component,
@Repository, @Autowired, @Service

Task 8:
What do you understand by IOC? Explain with diagram.. 
-> IOC is nothing but a software engineering architectural pattern, where we move the object 
creation, configuration controls from the Application Program to some external container.
TRADITIONAL APPROACH (Your code is the driver)
+--------------------------------------------------------+

|  [ Your Application Code ]                             |
|          |                                             |
|          +---> Uses 'new' keyword to create Object A   |
|          |                                             |
|          +---> Manually creates and injects Object B   |
+--------------------------------------------------------+

SPRING IOC APPROACH (The Container is the driver)
+--------------------------------------------------------+

|  [ Spring IoC Container ]                              |
|          |                                             |
|          |-- Instantiates Object A                     |
|          |-- Instantiates Object B                     |
|          |-- Injects Object B into Object A            |
|          v                                             |
|  [ Your Application Code ]                             |
|          |                                             |
|          +---> Simply requests/uses configured objects |
+--------------------------------------------------------+

Task 10:
What is DI in spring?
Dependency Injection (DI) is the design pattern used to implement Inversion of Control (IoC) in 
Spring. It is the process where the Spring container automatically delivers required external 
objects (dependencies) to a class, rather than making the class create them itself. Instead of 
using the new keyword inside a class to instantiate dependent objects, you let Spring "inject" 
those objects through constructors, setters, or fields.

Task 11:
How many types of DI do we have? Explain.
We have two types of DI in Spring. One is constructor Injection and Setter Injection.
/* constructor injection */
@Component
public class School {
    private final Student student;

    // Injected automatically at construction time
    @Autowired
    public School(Student student) {
        this.student = student;
    }
}

/* Setter Injection */
@Component
public class School {
    private Student student;

    // Injected after the School object is instantiated
    @Autowired
    public void setStudent(Student student) {
        this.student = student;
    }
}


Task 12:
What is Spring Application Configuration?
Application Configuration is the set of metadata, rules, and blueprints provided by the developer 
to instruct the framework on how to build the application. It explicitly defines which Java classes 
should be registered as managed components (Beans), sets their initial property values, and declares
how they depend on one another. It can be written using XML files, Java classes (@Configuration), 
or inline Annotations (@Component).

Application Context is the active, runtime container engine (defined by the ApplicationContext 
interface) that powers a Spring application. It reads the Application Configuration blueprints at 
startup, instantiates the specified Java objects in memory, injects their dependencies, manages 
their lifecycles, and serves them to the application. It acts as the central hub for all running 
components and offers advanced ecosystem features like internationalisation, resource loading, and 
event publishing.

Difference b/w Application Configuration and Application Context?
Application Configuration is the instruction manual that describes your objects, while the 
Application Context is the living machine that reads that manual to build and run your application.

What are the different ways to configure spring applications?
1. Annotation-Based Configuration (Declarative Style)
-> @Component, @Service, @Repository, @Controller, @Autowired
2. Java-Based Configuration (Programmatic Style)
->Key Annotations: @Configuration, @Bean, @ComponentScan, @PropertySource
3. XML-Based Configuration (Legacy Style)
->Key Tags: <beans>, <bean>, <property>, <constructor-arg>

Task 14: Why we need spring application copnfiguration?
-> We need Spring Application Configuration because the Spring IoC container is inherently empty when 
your application starts. Without configuration instructions, Spring has no way of knowing which Java
classes exist, how to create them, or how they connect to each other.

Task 16: What is bean scope .. give different scopes with description
A Bean Scope defines the lifecycle and visibility of an object instance managed by the Spring IoC
container. It controls exactly when a new instance of a bean is created, how long it lives in 
memory, and who gets to share it.

Threre are 6 scopes in Spring: Singleton, Prototype, Session, Request, WebSocket, Application
